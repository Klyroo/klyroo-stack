# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- Every documentation site is now one line of the Klyroo network, in the world of the showcase: black signage nav band with the wordmark and the plate of the line, the network menu, the library home as a black sign beside its own line diagram with the demonstration board restyled as signage, doc pages with the line diagram of the library as navigation, platform-sign breadcrumb, black code panels with a line-color gutter and previous and next stop signs, in light and station-night modes. The reading column is set in Public Sans (self-hosted, OFL) with a measure of about 70 characters; Archivo stays for titles, signs and navigation. The Klyroo.Display line on the stack map ends with "Players" (the block kinds moved to Klyroo.UI). The ground textures and the `texture` setting of `docs/site.yml` are gone (the key is still accepted and ignored).

### Added

- The Klyroo.UI component catalog has a Blocks family (`KlyHeading`, `KlyText`, `KlyStat<TValue>`, `KlyStatGroup<TValue>`, `KlyFacts`, `KlyBreakdown`, `KlyDiff`, `KlyRecordList`, `KlyList`, `KlyDateTile`, `KlyMeter`, `KlyImageGallery`), each with a runnable example, and new examples for what the existing components gained: `KlyAlert` details, action items and live region, the `KlyTimeline` pipeline, log and schedule layouts, `KlyImage.Caption`, the `KlyChart` funnel, `KlyTable` footers and Show more, `KlyUser` badge and contacts, `KlyAccordionItem.Text` and `KlyEmpty.ActionItems`. The generated skill reference (`skills/klyroo-ui/references/components.md`) comes from this catalog again instead of a hand patch.
- The code panel of every playground marks the lines that the last changed knob wrote, with `HighlightLines` of `KlyCodeBlock`: it compares each file with the text it showed before, shows the tab that changed and scrolls the first marked line into view. The Display playground is rebuilt around `KlyCodeBlock` (language, line numbers, emphasized lines, editable code), `KlySecretBlock`, `KlyFileList` with the file preview, and the audio and video players, and the component explorer of the Klyroo.UI playground has the typed blocks (stat, meter, facts, breakdown, diff, list, timeline with its schedule layout) with their own knobs.
- The home page boards of the documentation sites draw their code panel with `KlyCodeBlock` (line numbers, the lines of a chip emphasized through `data-highlighted`), and the Display board shows highlighted code with emphasized lines, the secret block and the file list. Every code block of every page is colored by the `CodeHighlighter` of Klyroo.Display.Core.
- A playground for the eight libraries, `playground/Klyroo.Playground`: a standalone Blazor WebAssembly app with one page per library, sample data, typed knobs, a live code panel and the state in the address. `build/publish-playground.sh <out-dir> [base-path]` publishes it for GitHub Pages with a `404.html` that restores the route and `.nojekyll`. The documentation sites link to it: a Playground link in the header and a "Try it in the playground" button on the home of each library, from `playground` in `libraries.yml`.

- `docs-site/Klyroo.Docs.Site`, the documentation site of the Klyroo libraries: it renders the `README.md`, `docs/*.md` and `docs/site.yml` of a library repository with the Markdown docs template of Klyroo.UI (titles from the first heading, GitHub heading ids, links between docs turned into routes and links to other files into GitHub addresses, a header that links to every library site, GitHub and NuGet, a search entry per page and per heading, a scrolling table of contents of the types for the API reference). `dotnet run -- --repo <library>` serves it and `-- export --repo <library> --out <folder>` writes it for GitHub Pages under `/<repo>/`, with `404.html` and `.nojekyll`, and fails on a missing page, asset, link target or anchor. `tests/Klyroo.Docs.Site.Tests` covers the reading and the export.
- `.github/workflows/docs-pages.yml`, a reusable workflow that checks out the calling repository, klyroo-stack and klyroo-ui, exports the site and deploys it with `actions/deploy-pages`; each library calls it from its own `.github/workflows/docs.yml`. A `docs/site.yml` for klyroo-stack itself.
- `KlyrooStackModule.AddOnPackages` and `KlyrooStackCatalog` entries for the packages `Klyroo.Stack` does not include: `Klyroo.UI.Server`, `Klyroo.UI.Images`, `Klyroo.UI.Images.Local`, `Klyroo.Query.EntityFrameworkCore`, the new `Klyroo.Form.DataAnnotations` and `Klyroo.Agent.AI` (the agent bridge as `Microsoft.Extensions.AI` functions). The README table "You need / Install", the concepts, platforms and FAQ pages and the installation page of the site list `Klyroo.Form.DataAnnotations` next to `Klyroo.UI.Server`, and a test checks that the hub and the Core meta-package depend on none of them.
- `tests/Klyroo.Stack.E2E` builds and runs again, and is in the solution with a `browser-tests` CI job (every push to `main` and by hand). It started the documentation site and the templates from folders that no longer exist (`playground/`, `templates/starter`, from before the repositories were split); it now starts `site/Klyroo.Stack.Site`, which runs the templates of `klyroo-ui` as demos. The browser tests of the templates themselves moved to `klyroo-ui/tests/Klyroo.UI.E2E`, and the demo tests here compile their checks from there.
- Browser tests of the typed forms of the `klyroo-saas` and `klyroo-admin` templates (`SaasAppTests`, `AdminAppTests`): the apps are generated with `dotnet new` from a local feed of the nine repositories and driven in a real browser (fill, validate, submit, cancel, error summary and focus).
- `KlyrooStackModule.AddOnPackages` and `KlyrooStackCatalog` entries for the packages `Klyroo.Stack` does not include: `Klyroo.UI.Server`, `Klyroo.UI.Images`, `Klyroo.UI.Images.Local`, `Klyroo.Query.EntityFrameworkCore` and the new `Klyroo.Form.DataAnnotations`. The README table "You need / Install", the platforms and FAQ pages and the installation page of the site list `Klyroo.Form.DataAnnotations` next to `Klyroo.UI.Server`, and a test checks that the hub and the Core meta-package depend on none of them.
- Documentation examples that bind Klyroo.UI inputs to the types of a model: `KlySelect` to an `int` foreign key (and an `int?`), an enum, a `Guid` and a `DateTime`, `KlySelectMenu` to a list of ints, `KlyInputMenu` to an `int?`, `KlyInputNumber` to `int`, `double` and `int?`, `KlyInputDate` to `DateTime` and `DateTimeOffset?`, and `KlySlider` to `int` and `float`; and an example of `KlyChart.OnSelect`.
- The MCP server also carries the hub documentation (`/stack/docs/<page>`: getting started, the templates, the options of every library), and a tenth tool, `resolve-module`, says which library, packages, template and skill own a component or a controller, from `KlyrooStackCatalog`.
- A CI job builds what a new user gets: it packs the nine repositories into a local feed, installs `Klyroo.Templates` from it, generates the saas, admin and headless templates in every interactivity mode, builds them with warnings as errors against that feed alone, requests their pages, and publishes and runs the headless app with NativeAOT (`build/pack-feed.sh`, `build/verify-templates.sh`).
- `build/build-stack-css.sh` rebuilds `klyroo-stack.css` from the sources of the sister libraries with the Tailwind binary of Klyroo.UI, then removes the rules `klyroo.css` already holds.
- The `klyroo-saas` and `klyroo-admin` templates are starters now, not one page: a Klyroo.UI shell (a header with navigation, or a resizable sidebar) with `KlyApp`, `KlyFormProvider`, `KlyFilePreviewProvider` and a color mode button, the stock .NET 10 Blazor Web App plumbing (`MapStaticAssets`, exception handler, HSTS, HTTPS redirection, `not-found` and `error` pages, `launchSettings.json`, `appsettings.json`, `.gitignore`), and pages that use each library the documented way: a dashboard with `DashboardController.LoadAsync`, `DashboardPersistence.Attach` and JSON type infos, a `KlyDataList` with a `Provider` (saas) or in-memory rows with selection and a sum row (admin), a `FormService` drawer to create and edit, `KlyDisplay` blocks, and a `KlySpreadsheetImport` (admin). The sample data is in memory.
- `--interactivity Server|WebAssembly|Auto` on both web templates. `WebAssembly` and `Auto` generate a server project, a `.Client` project that holds the pages and the sample data, and a solution file.
- `--product-name` on both web templates, and a product name derived from the project name (`MyShop` becomes "My Shop") instead of the raw namespace.
- The templates reference the Klyroo packages at the version of the `Klyroo.Templates` package: each `template.json` has a constant `KlyrooVersion` symbol, and a pre-pack target writes it from `$(Version)`. Nothing in a template carries a version of its own, and a test checks it.
- Tests of the template sources: each `template.json` names itself and takes its version from the placeholder, no template file has a hard-coded version, and the markup of the saas, admin and MAUI templates only uses classes that a stylesheet it loads defines.
- The MCP server carries the documentation pages of Klyroo.Query, Table, Form, Dashboard, Display, Spreadsheet and Agent (`/<library>/docs/<page>`), searchable with `search-documentation` and readable with `get-documentation-page`.

### Changed

- **Breaking for code that used it:** `KlyDisplay` and its types are gone from every consumer here. The site (live demos, hero stages, showcase, library docs, products page), the `klyroo-saas`, `klyroo-admin` and `klyroo-maui` templates and the playground use the typed components of Klyroo.UI and `KlyCodeBlock`, `KlySecretBlock` and `KlyFileList` of Klyroo.Display instead. `KlyrooStackCatalog` lists `KlyCodeBlock`, `KlySecretBlock` and `KlyFileList` for Display and the typed blocks for Klyroo.UI, so `resolve-module` finds each in its library, and `KlyDisplay` is no longer found.
- The documentation sites replaced their own regular-expression `SyntaxHighlighter` (copied from the docs template of Klyroo.UI) by the `CodeHighlighter` of Klyroo.Display.Core, and TOML fences are shown without color now since the highlighter has no TOML scanner. The token kinds map to the existing `--tok-*` colors of `DESIGN.md`.
- The result panels of the playgrounds that were `KlyDisplay` tables (Query, Spreadsheet, the index miniature) are typed `KlyTable` columns over records, and the facts are `KlyFacts`.
- **Breaking (documentation, samples, templates):** the templates, samples, site and documentation of this repository follow the strongly typed libraries (no `object` left in their public API except the boundaries listed in each repository), so what users copy is typed. The `klyroo-maui` page opens a `FormSchema<NoteForm>` through `FormService` and reads `outcome.Model`. The `klyroo-saas` and `klyroo-admin` forms are `FormSchema<AccountForm>` and `FormSchema<CustomerForm>` models that `FormService.CreateFormAsync` fills and returns as `outcome.Model`, the admin import is a `SpreadsheetImporter<CustomerRow>` whose `OnSubmit` receives `SpreadsheetRow<CustomerRow>`, the admin dashboard table is a `KlyDashboardTable<TopCustomer>` with `DashboardTableColumn.For` columns, the dashboard and chart enums replace their texts, and the headless template builds a typed `FormSchema`, `SpreadsheetSchema` and `FormController<Config>` under `PublishAot`. `build/verify-templates.sh` packs the nine repositories into a local feed, builds the six generated apps with warnings as errors, runs the five web apps and publishes the headless app with NativeAOT. It also generates `klyroo-maui` and compiles its Razor pages and layout against the feed in a plain Razor project (a stub stands in for `MauiProgram`), which needs no workload; when the `maui-android` workload is installed it builds the whole app for `net10.0-android` too (`SKIP_MAUI_BUILD=1` turns that off). The CI runner has no MAUI workload, so there the platform code, the XAML and the resources of the MAUI template are not built.
- The documentation site follows the typed APIs: the live demos, hero stages, showcase and docs pages build typed forms (`FormSchema.For<T>`, `FormController<T>`, `s.Step`, `s.Section`, `s.List`), typed importers (`SpreadsheetSchema.For<TRow>`), `KlyDataListFieldColumn` and `KlyDataListTemplateColumn`, `DataListGroupBy<T>.By(...)`, `KlyDashboardTable<TRow>`, `KlyChart<TItem, TIndex>` and `KlyColumn<TItem, TValue>`, and the enums that replaced closed sets of text (`ButtonType.Submit`, `InputType.Search`, `KlyElement.Div`, `KlyLinkTarget.Blank`, `KlyPlacement`, `KlyImageFormat.WebP`, `DisplayVariant.Secret`, `HeadingLevel`). The agent pages say that the model cannot write a sensitive field (unless it is named in `allowSensitiveWrites`) or a field of another step. The examples and the docs that were not compiled (snippets in the guides and in the library pages) are rewritten with the same APIs.
- The `KlyrooStackCatalog` descriptions and key components name the typed and Dynamic form types, the three data list column components and the typed Agent bridge types, and the benchmark and the integration tests use the typed schemas. The skill reference of Klyroo.UI (`klyroo-ui/skills/klyroo-ui/references/components.md`) is regenerated.
- The documentation site follows Klyroo.UI, whose select, select menu, input menu, listbox, number, date and slider components are generic: the examples whose `ValueChanged` is a method group or an untyped lambda name the type (`TValue="string"`), and the catalog documents `KlySelect<string>`, `KlyInputNumber<decimal?>` and so on. The component reference of the agent skill is regenerated.
- The XML documentation of `AddKlyrooStack` and the guides say how to configure the options of every library: a later `AddKlyrooDashboard(o => ...)`, `AddKlyrooDisplay(o => ...)` or `AddKlyrooForm(o => ...)` call configures the instances `AddKlyrooStack` registered.
- The `klyroo-maui` layout wraps the body in `KlyApp` with `KlyFormProvider` and `KlyFilePreviewProvider`, its `_Imports.razor` lists the namespaces of the other templates, and the page has a button that opens a form drawer. Its layout classes moved to `wwwroot/app.css`, because `min-h-dvh` and `max-w-3xl` are in none of the precompiled sheets.

### Fixed

- The documentation sites show everything whole on phones and desktops: install commands and package names wrap between words instead of ending in an ellipsis, wide tables and code blocks scroll inside the column with an edge fade that shows there is more, inline code breaks only between the words of a name, code in a table header or a heading keeps the look of its surroundings, the mobile breadcrumb wraps instead of cutting the page name, the lit station of the mobile strip is a full ring, a table with an empty header row has no header band, and a long rail or contents list fades at its foot. Code is set without ligatures.
- The library homes and the showcase: the nav wordmark keeps its distance from the menu button at 320 pixels, the boards wrap the address they write and show an edge fade on their tables and code, the feature descriptions start with a capital, the showcase title no longer lets a descender touch the next line, and headlines are balanced.
- The playground cuts nothing: the knob card takes its natural height, code and tables scroll sideways with an edge cue, pair cards stack at full width, the library tabs wrap on phones so the current one is always visible, select labels are short with the detail in the hint, the clean CSV sample imports clean, and the facts sample has a switch for its loading row.
- The audio demos of the Display pages and hero stage played nothing: the site referenced `/media/sample.mp3` and shipped no such file. `site/Klyroo.Stack.Site/wwwroot/media/sample.mp3` is a 50 second tone.
- `Styles/showcase.css` leaked into every docs page: its `.board` rule (the departure board of the showcase) gave the demonstration board of each library a black background and a border, and its `@property --lit` registered a number type for `--lit`, so the lit-line color of the boards (`color-mix(...)`) computed to 0 and no line was lit. The board rule is scoped to `.sc` and the showcase animation variable is `--sc-lit`.
- The documentation site keeps its yellow brand over the current Klyroo.UI theme: `Styles/site.css` sets `--klyroo-primary` to `#ffd23f` (with `#7a5800` as its text color in light mode, `#ffd23f` in dark mode, and `#151100` on the fill), and the focus ring uses the text tone, since the yellow is 1.4:1 on white. The text tokens stay those of Klyroo.UI.
- `site.css` of the documentation site had not been rebuilt since Klyroo.UI changed its theme, so the site still ran the old palette (a yellow primary and a warm gray text-dimmed at 4.41:1 on white). It is rebuilt from `klyroo.theme.css`, and the token table of `/docs/css-variables` and the tests that pin its values follow the current tokens.
- The platform list of the Klyroo.UI page said "Supported" for iOS, Windows and macOS, which nothing builds or runs yet. It says "Untested" again, and `PlatformsTests` requires that wording.
- The `/templates` gallery said "Starting" and offered "Preview Live" for a demo that is switched off or not published. It says "Demo offline" again, with no link to the demo, as `TemplatesPathBaseTests` expects.
- The browser tests no longer read colors in the middle of a color transition, scroll smoothly where a test reads a coordinate right after, or open a context menu with no room below the pointer without saying so (it flips above the pointer, and `ContextMenu_flips_above_the_pointer_where_the_viewport_has_no_room_below` covers it). The search test of the data list no longer sends its four keys one by one from the test process, where a busy machine could stretch one interval past the 300 ms debounce and make the list report twice, as it should. The test of a pause between two words types each word the same way, and the path base test of the template demos waits for the circuit of the gallery before it starts counting the sockets of the demo, where a late gallery socket was counted as the demo's. Every other browser test that types more than one key into a debounced field (inputs, input and select menus, the query state, the data list filters) now types in one task of the page through a shared `TypeInOneTask`, and the loading announcement of the remote menus is recorded by the page as it happens instead of being polled during the 400 ms the simulated source takes.
- The `klyroo-maui` template still used the removed dictionary `FormSchema`, `FormFieldSchema` and `outcome.FormData["text"]`, so a generated app did not compile. It declares a `NoteForm` and a `FormSchema.For<NoteForm>` and reads `outcome.Model`.
- `resolve-module` lists the add-on packages of a library in its Packages section, and `KlyrooStackCatalog.GetModule` resolves an add-on package name (`Klyroo.Form.DataAnnotations`, `Klyroo.UI.Server`, `Klyroo.Agent.AI`) to its library, as the tool description says.
- The spreadsheet benchmark had slowed down with the typed libraries (52.1 ms against 36.7 ms for the untyped importer, measured back to back). The cause was in `Klyroo.Spreadsheet.Core`, which read each number cell three times, and it is fixed there (27.3 ms, 12.4 MB allocated instead of 17.6 MB). `docs/benchmarks.md` has the comparison, the sizes of the `.Core` assemblies before and after the typing work and what the growth is made of, and `PRODUCT.md` and the site show the new figures.
- Every page of the documentation site had two `<main>` landmarks, one inside the other, and two elements with the id of the skip link: `SiteLayout` drew a `<main>` around the page, and `MainLayout` and `DocsLayout` each draw their own. `SiteLayout` draws none now, and `MainLayout` carries the same `data-interactive` marker as `DocsLayout`, which the browser tests wait on.
- The examples of the documentation site that put `KlyFormField` around an input still wrote `For="() => Model.X"`, a parameter that `Field` replaced: the attribute went to the HTML, the field was never bound, and its validation message never showed. They use `Field="FieldIdentifier.Create(() => Model.X)"`. The remote `KlySelectMenu` example with an `OptionsKey` passed the text `_country` instead of the value of the field, so the list never loaded again when the country changed.
- `klyroo-stack.css` lacked about fifty classes that the Dashboard, Display and Form components use (`max-h-80`, `bg-current`, `col-span-12`...), so some blocks rendered partly unstyled; it is now rebuilt from their sources.
- This changelog was emptied by a commit made while the disk of the build machine was full; it is restored with the entries of the changes made since.
- The templates linked `<KlyHead />` in `App.razor`, which renders nothing in a browser (it is the head content of a MAUI web view), so the pages had no theme variables and no color mode script. They use `KlyColorModeScript`, `KlyCultureMeta` and `KlyThemeStyle`, and the documentation says the same.
- `klyroo-stack.css` repeated 222 utility rules that `klyroo.css` already holds. Both sheets put them in one cascade layer, so the later copy won over the rules between them: the items of the header navigation and the search field of a data list were laid out wrongly. The sheet now only holds what `klyroo.css` lacks (41.9 KB to 27.8 KB), `build/dedupe-stack-css.mjs` rewrites it, and a test fails when a shared rule comes back.
- `KlyrooStackCatalog.TemplateShortName` named templates that do not exist; each library now points at the `Klyroo.Templates` template that shows it, and a test keeps it that way.
- `search-documentation` split camelCase words in the pages but not in the query, so a query such as `RegisterForm` found nothing.

- The `klyroo-maui` template generated a project that did not build: it had no `App` class, `MainPage`, `index.html` or platform folders. It is now a complete MAUI Blazor Hybrid app.
- The documentation site no longer lists `klyroo-behaviors.js` in Klyroo.Agent, which removed the module.

## [0.1.0-preview.1] - 2026-11-24

### Added

- `Klyroo.Stack` meta-package for Blazor Web and .NET MAUI Blazor Hybrid: `AddKlyrooStack()` registers Klyroo.UI, Query, Table, Form, Dashboard, Display, Spreadsheet and Agent in one call and accepts the option callbacks of Klyroo.UI and Klyroo.Table.
- `Klyroo.Stack.Core` headless meta-package that references the seven `.Core` engines, marked `IsAotCompatible` and `IsTrimmable`.
- `KlyrooStackCatalog`, which maps a component or controller name to the library, packages, template short name and agent skill that own it.
- `Klyroo.Stack.Mcp`, a `dotnet` tool (`klyroo-stack-mcp`) that serves the Klyroo.UI documentation to MCP clients over stdio: nine read-only tools, two prompts and four resources, with `--tools` and `--site-url` options.
- `Klyroo.Templates` with the `klyroo-saas`, `klyroo-admin`, `klyroo-headless` and `klyroo-maui` project templates.
- `klyroo-stack.css`, a precompiled stylesheet shipped with `Klyroo.Stack`, so apps need neither Node nor Tailwind.
- The `klyroo-stack` agent skill, which routes a coding agent to the skill of each library.
