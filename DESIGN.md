This file holds two separate design systems that share the docs-site build and the eight `library-*` colors and nothing else.

- **Docs family** (the first system, unprefixed tokens): every page of the eight library docs sites and the doc pages of klyroo-stack.
- **Organisation showcase** (the second system, `showcase-` tokens): the home page of a site with `home: showcase` in its `docs/site.yml`, today the klyroo-stack home at https://klyroo.github.io/klyroo-stack/.

When building a surface, follow the one system that governs it and do not borrow rules across.

# Design System: Klyroo library documentation sites

Scope: the static docs sites built by `docs-site/Klyroo.Docs.Site` for klyroo-ui, -query, -table, -form, -dashboard, -display, -spreadsheet and -agent, plus the doc pages of the klyroo-stack site. The home page of a site whose `docs/site.yml` sets `home: showcase` belongs to the showcase system further down. The Klyroo.Stack app under `site/` is a separate surface and is not covered here.

## Overview

**Creative North Star: "The Annotated Proof"**

Every site is the same calm, technical instrument: Geist on a near-black or cool off-white ground, hairline rules, Docus-style chrome (sticky header with a centered search pill, rail, column, table of contents). What changes per library is exactly three things, all driven by data in `libraries.yml` and each repo's `docs/site.yml`: the accent, the ground texture, and the demonstration board. The accent and the texture tell you which library you are on; the board tells you what it does.

The home page is built around proof. A two-line display headline (second line in the accent) sits left, the lead and the way in (accent button plus a copyable `dotnet add package` chip) sit right, and inside the first viewport at 1440x900 the board joins a C# code panel to two or three authored result panels with dotted accent leader lines. Selecting a feature chip lights the code lines and the result parts it produced. Everything below the board (showcases, the specification sheet, packages, the family list) is ruled by hairlines rather than boxed in cards. Doc pages are quieter still: the texture survives only as a band under the header.

Density is that of a developer tool, not a marketing page: small mono metadata, tabular numbers, short labels in sentence case, and results drawn as authored HTML marked "sample data" rather than screenshots.

**Key Characteristics:**
- One chromatic accent per site, derived into three contrast-checked tones (fill, ink, display).
- Both modes authored; dark is a near-black with a faint cool tint, light a cool off-white.
- Structure from 1px hairlines; only board panels and popovers are lifted.
- A ground texture taken from the library's own material, always masked away from running text.
- The demonstration board: code, chips, leader lines, lit results.

## Colors

A cool, nearly achromatic neutral system carrying a single library hue; the hue is data, the neutrals are fixed.

### Primary
- **The Library Accent** (one of `library-ui` emerald, `library-query` signal red, `library-table` electric cyan, `library-form` amber, `library-dashboard` violet, `library-display` pink, `library-spreadsheet` teal, `library-agent` indigo): written per site as `--accent` from `site.yml`. Used as a fill only: the Get started button, the mark tile, a pressed feature chip, the gutter dot on a lit code line, leader-line end dots, switches and step markers in board miniatures, sparkline points.
- **On-Accent Ink** (`on-accent`): near-black text on an accent fill; white when the accent is too dark for it (the derivation also darkens a mid-tone accent such as indigo until white reaches 4.5:1).
- **Accent Ink** (computed per library and mode; `accent-ink-default-light` is the fallback for Klyroo.UI): links, the current nav item, focus rings, the current TOC marker, leader-line strokes, `Core` package badges. Moved along lightness until it reaches 4.6:1 on the darkest surface text can sit on.
- **Accent Display** (computed; `accent-display-default-light` is the fallback): the second line of the hero headline only, held at 3.2:1 so it stays closer to the raw hue than the ink.

### Neutral
- **Ground** (`ground-light` / `ground-dark`): the page.
- **Raised** (`raised-light` / `raised-dark`): board result panels, menus, prev/next cards on hover, callout base.
- **Sunken** (`sunken-light` / `sunken-dark`): meter tracks, footer tint, the base of inline code.
- **Code Ground and Code Head** (`code-bg-*`, `code-head-*`): code blocks, the board code panel, the bar above a code block, table headers.
- **Strong / Text / Muted / Dim** (`strong-*`, `text-*`, `muted-*`, `dim-*`): headings and emphasis; body; leads, secondary copy and nav; line numbers, separators and mono notes.
- **Line and Line Strong** (`line-*`, `line-strong-*`): every hairline; the stronger one for control borders, chips and table header rules.
- **Danger** (`danger-*`): validation errors in board miniatures, invalid control borders, the over-budget meter fill.

### Tertiary: syntax and callouts
The syntax palette (`syntax-*-light` / `syntax-*-dark`) is fixed across the family, each tone at least 4.5:1 on code ground and raised. Callout kinds reuse four of its values: info uses the tag blue, success the string green, warning the number amber, error the variable red; the default callout uses the accent ink.

### Named Rules
**The One Library Hue Rule.** A site carries exactly one chromatic accent, the one in its `site.yml`. Other libraries' accents appear only as the small dots of the ecosystem menu, footer and family list.

**The Three Tones Rule.** The raw accent is for fills, never for text. Text and strokes use the accent ink, the headline's second line uses the accent display tone, and both are computed by `AccentColor` rather than picked by hand.

**The Neutral Lit Rule.** A lit code line, row, stage or block is a neutral fill (6% of strong). The accent appears only in the gutter dot and the leader lines, so a lit result never reads as an error or a selection.

## Typography

**Display Font:** Geist (with ui-sans-serif, system-ui)
**Body Font:** Geist
**Label/Mono Font:** Geist Mono (with ui-monospace, SFMono-Regular, Menlo)

**Character:** One grotesque at two temperatures: tight, heavy-ish display (weight 650 with negative tracking) over open, unhurried reading text, with Geist Mono carrying everything that is code or metadata about code.

### Hierarchy
- **Display** (650, up to 5.5rem, 0.99): the two-line hero headline, balanced, second line in the accent display tone.
- **Headline** (650, up to 3rem, 1.08): doc page title, max 24ch. **Section** (650, up to 2.5rem, 1.1) heads home sections; the close uses a 3.5rem variant at 1.04.
- **Title / Subtitle** (650 at 1.75rem; 620 at 1.3125rem; 1.22): Markdown h2 and h3. API types (h4 holding code) start under a hairline at 1.1875rem.
- **Lead** (400, 1-1.125rem, 1.55) on the home, 1.0625-1.1875rem at 1.6 on doc pages, in muted.
- **Body / Prose** (400, 1rem at 1.6 in the chrome; 1.0625rem at 1.72 in Markdown): running text held to 72ch.
- **Label** (600, 0.8125rem): panel titles, TOC heading, field labels, table headers. Sentence case, no tracking.
- **Code** (Geist Mono, 0.78-0.8125rem, 1.7) and **Code meta** (Geist Mono, 0.6875-0.75rem): file names, panel notes ("sample data", "16 lines"), feature chips, the install command, annotations.

### Named Rules
**The Tracking Follows Size Rule.** Negative tracking grows with size (-0.036em at display, -0.03em at section, -0.02em at small titles) and is zero at label size and below.

**The Mono Means Code Rule.** Geist Mono is reserved for things a developer would type or read in an editor: code, file names, package commands, chips that name API features, and notes about the code. Prose labels stay in Geist.

## Layout

A centered page of 88rem with a 1.5rem gutter (2rem from 1024px), under a sticky 4rem header split into three columns (brand, a search pill up to 28rem, actions). Below 768px the search collapses to an icon beside the actions and the ecosystem menu becomes a full-width sheet.

**Home.** The hero row is a 1.55fr / 1fr grid aligned on the bottom edge (stacked below 1024px). The board follows as a 5fr / 7fr grid with a 4.5rem column gap reserved for leader lines; "quick" boards with more code give the code at least 31rem and an even split. Sections below open with clamp(4rem, 8vw, 7rem) of top space. Showcases alternate code-and-text against a sticky result panel (5fr / 7fr, flipped every other one).

**Doc page.** One column on mobile with a sticky subbar for where you are; 15rem rail plus column from 1024px; rail, column and 14.5rem table of contents from 1280px. Rail and TOC are sticky under the header and scroll on their own.

**Rhythm.** Spacing is quiet and consistent rather than tokenized: 1rem inside panels, 1.25rem row padding in ruled lists, 2.5rem between showcases, 3.5rem above prose h2.

## Elevation & Depth

Flat by default, ruled by hairlines, with two lifted layers. Board panels (and the sticky showcase result) use a soft, wide, low-opacity panel shadow; menus use a slightly deeper pop shadow. In dark mode both shadows add a 1px inner top highlight so the panel edge catches light on near-black. The accent button carries a faint inner top highlight and an accent-tinted glow that lifts 1px on hover. The sticky header and mobile subbar use a 14px backdrop blur over an 82-90% ground so scrolling content stays legible beneath them.

### Shadow Vocabulary
- **Panel** (light `0 1px 2px rgb(15 23 42 / 0.05), 0 14px 32px -18px rgb(15 23 42 / 0.24)`; dark `0 1px 0 rgb(255 255 255 / 0.035) inset, 0 22px 44px -24px rgb(0 0 0 / 0.85)`): board panels and showcase results.
- **Pop** (light `0 2px 4px rgb(15 23 42 / 0.06), 0 20px 44px -16px rgb(15 23 42 / 0.3)`; dark `0 1px 0 rgb(255 255 255 / 0.05) inset, 0 28px 56px -20px rgb(0 0 0 / 0.9)`): the ecosystem menu and menus drawn inside boards.

### Named Rules
**The Hairline First Rule.** Lists of things (features, packages, showcases, family) are separated by a 1px line, not wrapped in cards. Only the board's panels and floating menus earn a shadow.

**The Ground Stays Behind Rule.** The library texture never sits behind running text. On doc pages it is a 6rem band under the header that fades out before the breadcrumb; on the home it lives in the gutters and below the top of the board, masked clear beneath the headline and lead. Its strongest line is 13% (light) or 15% (dark) of the accent.

## Shapes

Gently rounded, never soft. Three radii carry the chrome: 6px for nav items, inline code and small buttons; 10px for buttons, the install chip, code blocks, callouts and tables; 14px for board panels. Board miniatures (fields, menu buttons, the send button) use 8px, a step between. Pills (999px) are reserved for the search, feature chips, tags, facets, layer badges and annotations. Circles mark state: accent dots on lit lines, library dots in menus, radios and steps. Leader lines are dotted (1.5 on, 5 off, round caps, 1.5px) and end in an accent dot ringed in the ground color.

Each library's ground texture is drawn from its own material: blueprint grid (ui), dot matrix (query), ruled rows (table), field baseline grid (form), chart ticks (dashboard), halftone (display), cell grid paper (spreadsheet), node dots on a sparse graph (agent).

## Components

### Buttons
- **Shape:** gently curved (10px), 2.625rem tall, 1.125rem side padding, 0.9375rem at 600, optional trailing arrow icon.
- **Accent:** accent fill with on-accent text, inner highlight and accent glow; rises 1px on hover.
- **Outline:** line-strong border over a translucent raised fill, strong text; border shifts toward the accent ink on hover.
- **Focus:** 2px accent-ink outline, 3px offset.
- **Install chip:** the outline button's shape holding the `dotnet add package` command in Geist Mono and a copy icon that turns into an accent-ink check when copied.

### Chips
- **Feature chip (board):** a mono pill with a line-strong border and muted text; hover brightens text and tints the border; pressed fills with the accent and switches to on-accent text. Inert until the board script is live.
- **Tags, facets, layer badges:** small pills with a line-strong border on the ground; the `Core` layer badge takes the accent ink.

### Cards / Containers
- **Board panel:** 14px radius, 1px line border, raised fill (code panel on code ground), panel shadow. A 2.25rem head bar on a code-head tint carries a label-size title or a mono file name, and a mono dim note on the right ("sample data", "16 lines", "URL form of the same state").
- **Prev/next:** 10px radius, 1px line, translucent raised fill, accent-ink arrow; border tints toward the accent on hover.
- **Callout:** 10px radius, a 30% hairline and a 7% tint of its kind color over raised, the title in that color at 650.

### Inputs / Fields
- **Search pill:** 999px radius, line-strong border, translucent raised fill, muted label and Ctrl K keycaps; hover moves the border toward the accent ink.
- **Board miniatures:** 8px fields on the ground with line-strong borders; invalid fields take a danger border and a danger message below; radios, switches and steps fill with the accent when on.

### Navigation
- **Header:** mark tile in the accent with `klyroo/<name>` wordmark (dim slash), centered search, then Docs, API, the Klyroo ecosystem menu (each library with its accent dot), GitHub and theme toggle as 2.25rem icon buttons with an accent-soft hover.
- **Rail:** groups with icons and chevrons, pages hanging off a 1px line; hover is an accent-soft fill; the current page is accent ink at 600 on accent-soft with a 1px accent-ink marker on the line.
- **TOC:** 0.8125rem muted links on a 1px line, the current section in accent ink with the same 1px marker.
- **Mobile:** a sticky subbar under the header names the current page and opens the rail; the TOC becomes a collapsible box above the article.

### Code Block
10px radius on code ground with a code-head bar (mono file title left, ghost copy button right); 0.8125rem Geist Mono at 1.7; comments italic. Copy turns accent ink with a check when done.

### Demonstration Board (signature)
A code panel with numbered lines and a strip of feature chips with a one-line caption, beside two or three result panels. Choosing a chip lights the producing lines (neutral fill, accent gutter dot, bright line number) and the matching result parts, draws dotted accent leader lines from the lit lines to them across the column gap, and may show a mono annotation pill under the result. Results are authored HTML in the site's own look, labelled sample data. Leader lines hide below 1024px; the board is complete without its script. Lit transitions run 360ms on the shared ease-out curve, and annotation motion is dropped under reduced motion.

## Do's and Don'ts

### Do:
- **Do** take the accent and texture from `libraries.yml` / `site.yml` and let `AccentColor` derive the ink, display and on-accent tones for both modes.
- **Do** keep the board, headline, lead and install chip inside the first viewport at 1440x900.
- **Do** mark lit results with the neutral lit fill and put the accent only in gutter dots, leader lines and fills.
- **Do** separate list content with 1px hairlines and keep running text to 72ch.
- **Do** label drawn results as sample data in the panel head note, and draw them as HTML in the site's look.
- **Do** use the shared ease-out curve (cubic-bezier(0.16, 1, 0.3, 1)) at 140-200ms for hover and 360ms for lit states.

### Don't:
- **Don't** set text in the raw accent; use the accent ink or, for the headline's second line only, the accent display tone.
- **Don't** introduce a second chromatic accent on a site, or reuse another library's accent beyond its menu dot.
- **Don't** let the ground texture run behind the headline, lead, breadcrumb or prose.
- **Don't** wrap features, packages or showcases in shadowed cards; only board panels and menus are lifted.
- **Don't** use hard offset shadows; elevation here is soft and diffuse.
- **Don't** add uppercase tracked labels or eyebrows above headings; labels are sentence case at 600.
- **Don't** put screenshots in the board or invent numbers in it.

# Design System: Klyroo organisation showcase

Scope: the home page of a site whose `docs/site.yml` sets `home: showcase`, today only the klyroo-stack site (https://klyroo.github.io/klyroo-stack/). It is built by `docs-site/Klyroo.Docs.Site/Components/Showcase` and styled by `Styles/showcase.css`, where every rule sits under `.is-showcase` so nothing leaks into the docs pages of the same site. Its tokens carry the `showcase-` prefix in the frontmatter; the eight library colors are the shared `library-*` tokens. Nothing in the docs-family system above applies here, and nothing here applies to the docs pages.

## Overview

**Creative North Star: "The Network Diagram"**

Klyroo is drawn as a transit network in the Beck and Vignelli grammar: each library is a colored line whose stations are features its README really lists, and Klyroo.Stack is the interchange where all eight meet. The page is signage rather than marketing: black sign panels in both modes, the system yellow on the warm signage-white ground in light and a station-night ground in dark, a condensed grotesk whose width axis sets how loud a sign is, and JetBrains Mono for anything a developer types.

The map is the page. It fills the right of the first viewport beside a black "Choose your line." sign and a platform sign holding the install command, then stays sticky while eight chapter cards scroll past on the left and the camera rides each line in turn, lighting its stations as the chapter is read. After the journey the page keeps the grammar for everything else: the four rules are four parallel tracks, the templates a departure board, the close the whole network pulled back above a legend of strips. Motion is strong and scroll-driven, and every effect has a still equivalent.

The geometry is data. `NetworkData.cs` holds the lines, legs and stations, `NetworkLayout.cs` computes paths, labels, badges, cameras and the journey keyframes in C#, and no coordinate is written by hand.

**Key Characteristics:**
- One system color (the yellow) for the network itself; the eight library colors only for lines.
- Black signage panels with white Archivo, identical in both modes.
- Lines at 0, 45 and 90 degrees with rounded bends, white station ticks ringed in ink, an interchange disc.
- Width axis as the hierarchy: wider is louder.
- Trains and a rider moving along the real routes; a hovered or focused line isolates itself.
- Depth from solid rings and outlines, never blurred shadows.

## Colors

A warm, near-achromatic signage palette carrying one system yellow and eight line colors that belong to the libraries.

### Primary
- **System Yellow** (`showcase-system-yellow`): the color of the network, never of a line. The interchange disc, the 6px band under the nav, the full stop of the hero, the platform number, the platform edge of a chapter card, the head of the "Change here for" board and the departure board, template kind tags, the GitHub and "Read the docs" buttons, lit stations, the train's nose and the rider, link underlines on hover, text selection, and the focus ring on black panels and in dark mode.

### Secondary
- **The Eight Line Colors** (`library-*`, the same tokens as the docs family): the routes, line badges, the color strip of a chapter card, the rail of its stops, the hero bar under the headline, the philosophy tracks and the legend strips. The fill on a badge and the text on it come from `AccentColor.Compute`, so a dark accent such as indigo carries white text and a light one carries ink.

### Neutral
- **Signage Ink** (`showcase-ink`): every sign panel in light mode, the nav band in both modes, station and badge outlines in light mode, the outline of the train body.
- **Signage White and Station Night** (`showcase-ground-light` / `showcase-ground-dark`): the page grounds. **Sunken / Raised** (`showcase-sunken-*`, `showcase-raised-*`) feed the Klyroo.UI components on the ground.
- **Text / Strong / Muted** (`showcase-text-*`, `showcase-strong-*`, `showcase-muted-*`): copy, section headings, ledes and proofs on the ground.
- **Line** (`showcase-line-*`): hairlines on the ground, legend row rules.
- **Station** (`showcase-station-light` / `showcase-station-dark`): the fill of a station tick; in dark mode the same cream is also the outline of ticks, badges and the interchange ring.
- **Dark Panel** (`showcase-panel-dark`): sign panels in dark mode, each with a 1px `showcase-line-dark` outline so the panel edge holds on the night ground.
- **Panel Text / Panel Muted / Panel Line** (`showcase-panel-text`, `showcase-panel-muted`, `showcase-panel-line`): copy, secondary copy and hairlines on black panels. **Stop Unlit** (`showcase-stop-unlit`) is a chapter station title before it lights, mixing to white as it does.
- **Code Well** (`showcase-code-well`): code blocks, the install row of a chapter card and the departure board body, one step darker than the panel.
- **Focus Blue** (`showcase-focus-light`): the focus ring on the light ground only, where yellow would not reach contrast on signage white. In dark mode and on black panels the ring is the system yellow.

### Named Rules
**The System Yellow Rule.** The yellow belongs to the network: the interchange, platforms, signs and lit states. It is never the color of a line, and no line color is ever used for a sign.

**The Black Sign Rule.** Signs are black in both modes: ink in light, the dark panel with a 1px outline in dark. Klyroo.UI components inside a sign are re-tokened to panel colors rather than restyled one by one.

## Typography

**Display Font:** Archivo variable (width axis 62 to 125), loaded locally from `Fonts/ArchivoVariable.woff2`, falling back to ui-sans-serif, system-ui
**Body Font:** Archivo
**Label/Mono Font:** JetBrains Mono (with ui-monospace, SFMono-Regular, Menlo)

**Character:** One signage grotesk stretched and condensed by its width axis, heavy (800 to 900) on signs and plain (400 to 500) in running copy, with a code mono kept for commands and template names.

### Hierarchy
- **Display** (`showcase-display`): the hero sign only, white on black, balanced, the full stop in yellow.
- **Headline** (`showcase-headline`): section heads ("Four rules hold the network together."), max 20ch, strong on the ground and white on the templates band.
- **Wordmark** (`showcase-wordmark`): `klyroo/stack` in the nav, the `/stack` in yellow; the interchange text and the platform number share its 125 width at 900.
- **Sign title** (`showcase-sign-title`): track boards; the "Change here for" and departure-board heads use the same 118 width at 900, 1 to 1.125rem.
- **Line pill** (`showcase-line-pill`): the library name on a chapter card; 1.0625rem in the legend, 14.5px at 800 and width 108 on map badges.
- **Nav** (`showcase-nav`): nav links in white with a 3px yellow underline on hover.
- **Station title** (`showcase-station-title`): a stop in a chapter card; ways out ("Next line") share width 108 at 700.
- **Map label** (`showcase-map-label`): station names on the map at normal width, ink in light and `showcase-label-dark` in dark, rotated 45 degrees where the line runs horizontally.
- **Lead / Body** (`showcase-lead`, `showcase-body`): opening copy and section ledes at 500; stop descriptions, proofs and template text at 400, 0.9375 to 1rem, held to 52 to 70ch.
- **Code** (`showcase-code`, `showcase-platform-command`): code blocks and install rows; the platform command at 700 in white; template names on the departure board at 800, 1.375rem, in yellow.

### Named Rules
**The Wider Is Louder Rule.** The width axis is the hierarchy: 100 for map labels, 108 for station titles, badges and ways out, 112 for nav and line pills, 118 for section heads and sign titles, 125 for the hero, the wordmark, the interchange and the platform number. Weight follows the same order; size alone never carries a sign.

**The Mono Is Typed Rule.** JetBrains Mono sets only what a developer types or reads in a terminal: install commands, code blocks, template names. Signs, stations and labels stay in Archivo.

## Layout

The page has no centered container at the top: the journey is a full-bleed 5fr / 7fr grid under a sticky 62px nav band (56px of band plus the 6px yellow rule), with a gutter of `showcase-gutter`. The opening (the sign, two lines of copy with the hint, the platform sign pinned to the bottom) holds the left column for one screen. The stage, the map plus the pillars panel at its top right, is sticky across the whole journey and spans the page; the map itself occupies the right 58.3%. Each of the eight chapters is one screen tall in the left column, card vertically centered. After the journey, sections use `showcase-section` top padding and a 78rem wrap: the philosophy tracks as a 16rem board / text / 30rem demo grid, the templates as 4fr / 8fr on a full-bleed black band, the close as 4fr / 7fr copy and map above the legend.

**Responsive.**
- Below 1100px the tracks, templates and close stack to one column.
- Below 1000px the nav links fold into a menu button.
- At 820px and below the journey is switched off: opening, then a compact interchange (the disc and eight stubs ending in badges) and a vertical line diagram (one rail per line, stations stacked) in place of the map, the pillars panel in the flow, chapters as plain full-width cards with every stop lit; the close map is hidden and search leaves the nav.
- Below 700px legend rows stack and the departure board's type column narrows to 5rem.
- Below 520px and 360px the wordmark shrinks, and at 360px GitHub becomes icon only with its label kept for screen readers.

### Named Rules
**The Map Is The Page Rule.** The network takes the right two thirds of the first viewport and stays on screen through the journey. Content arrives beside it on black signs; it is never shrunk into a hero illustration or replaced by a grid of library cards.

## Elevation & Depth

Flat signage with no blurred shadows anywhere. Depth comes from color blocks (black signs on a light ground, cream outlines on a night ground) and from solid rings drawn with zero-blur box-shadows or SVG strokes: the platform sign sits in a 4px ink ring (panel line in dark), a template roundel in a 3px white ring, a chapter stop in a halo of its line color that widens as it lights. Layering is z-index only: the chapter cards ride above the sticky map, and during the journey the map fades out over 130px toward the card edge (a mask, not a shadow) so labels never cut mid-word.

### Shadow Vocabulary
- **Platform ring** (`box-shadow: 0 0 0 4px #111111`; dark `0 0 0 4px #34373f`): the platform sign.
- **Roundel ring** (`box-shadow: 0 0 0 3px #ffffff`): the roundels of the "Change here for" board.
- **Stop halo** (`box-shadow: 0 0 0 calc(2px + var(--lit) * 2px)` in the line color): a station dot in a chapter card.

### Named Rules
**The Ring Not Shadow Rule.** Every edge is a solid ring or outline at zero blur. A soft drop shadow would make a sign float; signs are bolted to the wall.

## Shapes

Lines are 14 map units wide with round caps and joins, run only at 0, 45 and 90 degrees, and turn through quadratic bends of radius 20. A station is a white disc (r 6.5) with a 3.5 ink stroke; the interchange is an ink ring (r 50) around a yellow disc (r 41). Badges are 34-unit plates with 8-unit corners and a 3.5 outline. The HTML echoes the map: chapter stops ride a 6px rail of the line color, the line diagram a 14px rail, legend strips 12px, philosophy tracks 14px, each with ink-ringed station circles.

Panels round by size: 18px (`showcase-sign`) for the hero sign and chapter cards, 14px (`showcase-panel`) for the platform sign, pillars panel and departure board, 12px for the "Change here for" board, 8px (`showcase-control`) for badges, track boards and Klyroo.UI controls, 6px (`showcase-tag`) for template kind tags and small hit areas. The platform number is a yellow square flush with its black body; a chapter card opens with a yellow platform edge (0.75rem, ink ticks every 1.05rem) over a 0.5rem strip of its line color.

### Named Rules
**The 45-Degree Rule.** A line only runs at 0, 45 or 90 degrees and only bends through a rounded corner. Geometry is computed from `NetworkData` legs; never hand-place a coordinate.

## Components

### Navigation (station-sign band)
- **Style:** ink band in both modes, `klyroo/stack` wordmark left, Libraries, Philosophy, Docs, Playground as white Archivo links with a 3px yellow underline on hover, then search, color mode and a yellow GitHub button. A 6px yellow rule closes it.
- **Focus:** 2px yellow outline.
- **Mobile:** links fold into a ghost menu button below 1000px; search leaves at 820px.

### Signs and panels
- **Hero sign:** black panel, the display headline with its yellow full stop, and a 10px bar of the eight line colors in map order.
- **Platform sign:** a yellow square holding the platform number, a black body with the install command in white mono and a yellow copy button whose icon turns to a check; the closing copy reuses it with an "All packages" popover.
- **Pillars panel:** a small black panel at the top right of the stage, four rules each with a yellow dot, hairlines between, yellow on hover, each linking to its track with the rule in a tooltip. It fades out as the journey starts.

### Line badge (signature)
A plate in the line color with its outline and the library name, the end of every line on the map, in the compact interchange, the line diagram, chapter cards and the legend. Hover thickens the outline from 3.5 to 6; focus draws a separate ring (3 units, Focus Blue in light, yellow in dark). Hovering or focusing a badge, or hovering its line, isolates the line.

### Chapter card
Black card, 34rem max: platform edge and line strip on top, the line pill and the library's tagline, the stations as a numbered rail (dot, bold title, one-line description), "Read the docs" (yellow) and "Open the playground" (outline) with trailing arrows, the install row on the code well with a ghost copy button, and a foot with "Back to the interchange" and "Next line" in white with yellow arrow icons.

### Trains, rider and isolation
- **Train:** a dark capsule (26 by 11, white 2px stroke) with a yellow nose; one per line, leaving from under the interchange and resting under its badge so it never sits on a station.
- **Rider:** a yellow disc with an ink ring that carries the reader along the line being read during the journey.
- **Isolation:** the other lines drop to 14% opacity over 0.3s, and the isolated line's stations turn yellow, grow 1.45x and give their labels a 7px yellow halo. In the line diagram other lines drop to 30% and stops turn yellow at 1.3x.

### Boards after the journey
- **Track:** a full-width line in the color of a library (headless first on Query, typed end to end on Form, every render mode on UI, operable by AI on Agent), a station circle at its start, a black track board with a yellow top stripe and arrow, the rule in strong 1.25rem and its proof below.
- **Change here for:** a black board with a yellow head, each row a roundel in a line color and the package with its command.
- **Render modes:** five stops on one short line, each a button with a yellow wash on hover and a tooltip.
- **Departure board:** a yellow head (Type, Template and what it creates), rows on the code well with a yellow kind tag, the template name in yellow mono, what it creates, and its command.
- **Legend:** per line, the badge, a strip with its stations as ticks and names, the tagline, and underlined Docs and Playground links whose underline turns yellow on hover.

### Buttons
Klyroo.UI buttons re-tokened by the showcase: primary is the yellow fill with ink text at the 8px control radius, outline on a black sign draws its edge and label in yellow ("Open the playground"), ghost is used for copy and menu buttons. Focus rings are 3px at 3px offset, Focus Blue on the light ground and yellow on black or night.

### Motion
- **On load** (stage map only): each line draws in over 1.2s on the shared ease-out curve (cubic-bezier(0.16, 1, 0.3, 1)), staggered per line; each station fades in as the line reaches it; badges appear 1s after their line starts.
- **Trains:** start 1.8s after load plus six times the line's delay, travel for two thirds of a period proportional to the line's length (length / 45 + 3.5 s) on an in-out curve, then rest.
- **Journey:** one view timeline over the journey section drives the camera (overview, then the interchange, then a hold framed on each line, scale 1.12 to 1.9), the line opacities (ridden line 1, neighbours 0.55, the rest 0.16), the rider, and stations lighting one after another; chapter stops light as each enters the viewport.
- **Close:** the camera pulls back from 1.7x to 1x and the lines draw in as the section enters view.
- **Reduced motion, no scroll-timeline support, or 820px and below:** no drawing, no trains, no camera. The map is the static overview beside the opening, chapters are plain cards below it with every stop lit, and isolation on hover and focus still works.

### Named Rules
**The Train Is Not A Station Rule.** A moving thing is a capsule with a yellow nose, never a disc, and it never rests on a station tick.

**The One Line Lit Rule.** At any moment only one line has lit stations and labels: the one hovered, focused or being ridden. The others dim.

**The Still Map Rule.** Every effect has a still equivalent that keeps the content: the static map, the lit stops, the plain chapters. Motion adds the ride; it never carries information alone.

## Do's and Don'ts

### Do:
- **Do** derive lines, stations, badges, cameras and journey keyframes from `NetworkData` and `NetworkLayout`; every station on the showcase is a feature listed in its library's README.
- **Do** keep the yellow for the network (interchange, platforms, signs, lit states, primary actions) and the eight library colors for lines on the showcase.
- **Do** set showcase signs in Archivo with the width axis, wider for louder, and keep JetBrains Mono for commands and template names.
- **Do** keep showcase signs black in both modes, with a 1px panel-line outline in dark.
- **Do** give every showcase motion a still state under reduced motion, without scroll timelines, and at 820px and below.
- **Do** use Focus Blue for focus on the light showcase ground and the yellow on black panels and in dark mode.

### Don't:
- **Don't** use the system yellow as a line color, or a line color for a sign, on the showcase.
- **Don't** draw a showcase line at any angle other than 0, 45 or 90 degrees, or bend it without a rounded corner.
- **Don't** put a blurred drop shadow on a showcase surface; depth is solid rings and black panels.
- **Don't** let a train or the rider rest on a station, or draw them as discs.
- **Don't** replace the map with a hero illustration or a grid of library cards.
- **Don't** add uppercase tracked labels or eyebrows above showcase headings; signs speak through width and weight.
- **Don't** invent stations, numbers, logos or testimonials on the showcase.
